# ADR-0018: Databases — SQLite Embedded Default, PostgreSQL for Teams

- **Status:** Accepted
- **Date:** 2026-08-30
- **Deciders:** Aether Architecture Review Board
- **Supersedes:** —
- **Superseded by:** —

## Context

The Engineering Graph, the event log, and the artifact index all require durable storage. The default must work in air-gapped single-user environments (workstations, factory cells); teams need a different default.

## Decision

The platform SHALL use **SQLite (WAL mode, embedded)** as the default storage backend for single-user / workstation deployments, and **PostgreSQL 16+** for team / factory cell deployments. Both are reached through a **single storage SPI in the kernel**.

**Rationale (SDP §4.2, §3.5):**

| Concern | Workstation | Team / factory |
|---|---|---|
| Graph store | Embedded SQLite (WAL) | PostgreSQL 16+ |
| Artifact store | Local CAS directory | Local CAS + S3-compatible object store (MinIO, air-gapped) |
| Event log | SQLite append-only table | PostgreSQL append-only partitioned table |
| Search | SQLite FTS5 | PostgreSQL full-text + trigram |

- **Zero-dependency default** honors air-gap and workstation use
- **Single storage SPI** keeps the contract surface uniform; AQL (§3.5) maps to both backends
- **SQLite's WAL** supports the 10M-node scale test (walking skeleton b)

**Constraints:**

- SQLite is bundled via `rusqlite` with the `bundled` feature — no system SQLite dependency at runtime
- PostgreSQL connection details (when used) are read from the layered config; never hard-coded
- All SQL is generated by the kernel's storage SPI; plugins never issue raw SQL (I-3)
- Migrations are first-class artifacts; their content is part of the provenance chain

## Consequences

- Positive: zero setup for a workstation user
- Positive: a single SPI means a new backend (e.g., a future embedded graph engine) is one crate
- Negative: SQLite has limits; the 10M-node scale test (Phase 0 walking skeleton b) is the standing CI guard
- Negative: PostgreSQL brings operational complexity (cluster, backups, replication)

## Enforcement

- Walking skeleton (b) validates SQLite at 10M-node scale (Phase 0)
- All SQL access goes through the storage SPI; raw SQL in plugins is rejected by `import-linter`
- Migration scripts are signed; the registry refuses unsigned migrations
