# S-3: Zero hard-coupling

**SDP §23 criterion**: Domain modules never import another domain's
implementation; communication is through contracts and Engineering
Graph objects only.

## Mechanism

The dark-build CI runs two enforcement layers:

1. `import-linter` rules (contract layer rules): the dependency
   graph between crates must respect the layering. The kernel
   may not depend on a domain crate; a domain crate may not depend
   on another domain crate.
2. Prohibited-token scan: the build fails if `if solver == X`,
   `is_nvidia`, `cad_vendor`, `gpu_model`, or similar patterns
   appear in the source.

## Evidence

- `infra/fitness/token_scan.py` — the prohibited-token scanner
  (fails on `solver ==`, `is_nvidia`, `cad_vendor`, `gpu_model`,
  `hostname`, `queue_name`).
- Cargo's `cargo tree` produces the dependency graph; the
  `import-linter` config is in `pyproject.toml` and
  `conftest.py`-equivalent for Rust (Cargo's own `[[bin]]` /
  `[lib]` `path` directives).

A regression that adds a vendor-specific branch in a domain
crate fails the dark-build. The kernel is allowed to depend on
`aether_exec` and `aether_graph`; domain crates (optimizer,
twins, surrogate, etc.) are not allowed to depend on each other.
