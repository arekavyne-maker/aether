# S-6: Hardware-agnostic execution

**SDP §23 criterion**: Workflows and plugin manifests declare
**computational requirements** (memory_gb, cores, parallelism,
accelerator_class, architecture), never hardware identifiers.

## Mechanism

The `requires` block in an AWL step and the resource-descriptor
schema (`contracts/compute.backend/`) explicitly forbid
hardware names. The prohibited-token scan in the dark-build
catches `gpu_model`, `hostname`, `queue_name`, and `cad_vendor`
in the source.

## Evidence

`contracts/compute.backend/schema/resource-requirement.schema.json`:

```json
"not": {
  "anyOf": [
    {"properties": {"gpu_model": {"type": "string"}}},
    {"properties": {"cpu_vendor": {"type": "string"}}},
    {"properties": {"hostname": {"type": "string"}}},
    {"properties": {"queue_name": {"type": "string"}}}
  ]
}
```

A workflow document with `gpu_model: "H100"` is **rejected** by
the resource-requirement schema. A plugin manifest with
`cad_vendor: "..."` is **rejected** by the plugin-manifest schema.

## Prohibited-token scan

`infra/fitness/token_scan.py` walks the source tree and asserts
none of the prohibited tokens appear in any source file (with
`# noqa: AETHER token-scan` for legitimate uses, of which there
are none in the kernel).
