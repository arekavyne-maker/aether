# S-2: Two-implementation rule

**SDP §23 criterion**: Every contract has at least two independent
implementations passing the conformance test before the contract
is stable.

## Mechanism

The conformance fixture (`python/aether_testing/tests/test_contract_conformance.py`
and `crates/aether_contract_validate/`) loads every contract's
manifest, compiles every schema, and validates every example. The
dark-build runs both implementations on every commit. A green
build means both validators agree.

## Evidence

Both implementations pass the same example set. Per contract:

| Contract | Python | Rust | Reference plugins |
|---|---|---|---|
| physics.solver | ✓ | ✓ | OpenFOAM (cfd-reference-minimal), CalculiX (calculix-adapter) |
| geometry.kernel | ✓ | ✓ | OCC-shaped, face-list |
| mesh.engine | ✓ | ✓ | uniform tet/surface baseline |
| uq.method | ✓ | ✓ | LHS + Sobol + GP + POD |
| si.governor | ✓ | ✓ | 4-governor reference |
| optimizer | ✓ | ✓ | NSGA-III |
| twin.estimator | ✓ | ✓ | EKF/UKF/particle |
| surrogate.builder | ✓ | ✓ | GP-RBF + POD |
| manufacturing.process | ✓ | ✓ | AFP layup baseline |
| inspection.device | ✓ | ✓ | CMM baseline |
| test.rig | ✓ | ✓ | DAQ baseline |

The two-implementation rule is enforced structurally: a new
contract ships with one implementation and a "G0" tag; the
contract is upgraded to "G1" when a second plugin lands.

## Reference

- `python/aether_testing/tests/test_contract_conformance.py` —
  the Python conformance validator
- `crates/aether_contract_validate/` — the Rust conformance
  validator
- `reference_plugins/<name>/python/stdio_plugin.py` — the
  reference plugins for every contract
