# S-7: Physics-first, fidelity-honest

**SDP §23 criterion**: Every quantitative claim carries an explicit
fidelity, validity envelope, and uncertainty statement. Surrogates
never silently replace physics; the result schema distinguishes
high-fidelity results, ROM outputs, and surrogate predictions.

## Mechanism

The result schemas (`contracts/physics.solver/schema/result-bundle.schema.json`,
`contracts/uq.method/schema/result.schema.json`, etc.) require:

- `fidelity_class`: `measurement` | `high_fidelity` |
  `medium_fidelity` | `low_fidelity` | `surrogate` | `rom` |
  `heuristic`.
- `uncertainty`: a structured object with method and bands.
- `envelope`: a declared region of validity.

The conformance test asserts these fields are present in every
result bundle. A plugin that returns a result without
`fidelity_class` is rejected by the schema validator and fails the
conformance fixture.

## Evidence

`python/aether_testing/tests/test_contract_conformance.py`:

```python
def test_physics_solver_result_requires_fidelity_metadata():
    bad_doc = {"run_id": "...", "produced_at": "...",
               "outputs": {"scalars": [], "fields": []},
               "provenance_ref": "..."}
    # Missing fidelity_class, validation_status, uncertainty.
    r = validator.validate("aether.physics.solver", schema_id, bad_doc)
    assert not r.valid
```

A green conformance test means every result bundle has
`fidelity_class` + `uncertainty` + `validation_status`. The
fitness pipeline (step 11) reports the per-crate LOC and runs the
prohibited-token scan; a regression that strips these fields
fails the build.
