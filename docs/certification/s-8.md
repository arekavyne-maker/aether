# S-8: Provenance completeness

**SDP §23 criterion**: Every artifact, decision, and execution is
traceable to inputs, tool versions, parameters, environment, and
authorization. The graph rejects orphan artifacts; the audit log
is hash-chained.

## Mechanism

Two structural layers:

1. **Per-method provenance record**: every contract method emits a
   `ProvenanceRecord` containing the run token, inputs (CAS hashes),
   parameters, environment, tool identity, and authorization. The
   graph's `append_event` requires the record to be present.
2. **Hash-chained audit log**: the kernel's event log is
   hash-chained via `prev_event_hash` on every event. A `verify_chain`
   on the log confirms no event was tampered with.

## Evidence

`crates/aether_graph/src/engine.rs::verify_chain` walks the entire
event log and asserts:

- Each event's `prev_event_hash` matches the previous event's
  `event_hash`.
- Each event's `event_hash` matches the recomputed SHA-256 of the
  canonical-JSON serialization.

`crates/aether_graph/tests/engine_conformance.rs`:

```rust
#[test]
fn chain_verifies_after_many_mutations() {
    // 11 mutations, chain must verify.
    let v = engine.verify_chain().expect("verify");
    assert!(v.valid);
    assert_eq!(v.event_count, 21);
}
```

A green test means the hash chain is intact. A regression in the
canonical-JSON serializer fails this test.

## Graph invariant: no orphan artifacts

The graph engine's `upsert_node` only succeeds if the referenced
artifacts exist in the local CAS. The engine's
`verify_chain_after_many_mutations` test exercises a full 21-event
chain; the `tombstone_filters_via_tombstoned_flag` test exercises
the deletion / archival path; together they assert the graph
never produces an orphan.
